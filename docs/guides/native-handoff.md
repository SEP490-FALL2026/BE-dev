## 2. File bạn phải nhận (có phiên bản trong repo BE)

Đọc theo thứ tự: `AGENTS.md` → `docs/rules/README.md` + `docs/rules/context.md` (+ rules chuyên đề gói chạm tới) → `docs/README.md` (nhãn trạng thái, chỉ mục ADR) → ADR-0005…0010 → design v1.2 → kế hoạch giao dev → test guide → maintenance guide → [walkthrough nghiệp vụ](native-business-walkthrough.md) (bảy kịch bản đi từng bước US/AC → API → dữ liệu → test, kèm bảng finding `W-xx` và trạng thái chốt) → fixtures `docs/examples/employee-import/`. Kiến trúc nền: `ARCHITECTURE.md`, `docs/architecture/backend-architecture-spec.md`, `docs/guides/kien-truc-backend-va-cach-viet-code.md`, ADR-0001…0004.

> **Cảnh báo về Git.** Tại thời điểm soạn, các file native và ADR-0005…0010 là **untracked** hoặc đã sửa chưa commit. Một checkout từ Git **không có** chúng cho tới khi Owner quyết định commit hoặc chuyển cho bạn. Manifest ghi **commit baseline** của hai repo và trạng thái git của từng file (`gitState`). **Chốt tài liệu khác với commit/push dùng chung (do Owner quyết định); không tự commit hộ.** Khi chưa commit, COORDINATOR chuyển tài liệu bằng gói ZIP (`--bundle` rồi nén): bố cục giống workspace (`Code/BE-dev-software-license-management/…`, `Docs/…`) để link giữa hai repo vẫn đúng sau khi giải nén. Người nhận **không chép đè mù**: đọc `BUNDLE-README.md` trong gói, chạy `--check` trong bản giải nén, rồi `--compare <BE checkout> <Docs checkout>` (chỉ đọc) để biết file nào SAME / NEW / DIFFERENT / DIFFERENT+LOCAL, xem `git diff --no-index` các file khác, hợp nhất tay file có thay đổi cục bộ, chép xong chạy `--check --docs <Docs root>`. Báo cáo phiên (`Docs/Reviews/…`, bị Git bỏ qua) chỉ có trong gói và chỉ mang tính tường thuật.

Thư mục `docs/workspace/` bị Git bỏ qua: bạn không cần nó.

## 4. Quy tắc làm việc (rút gọn — bản đầy đủ ở rules)

- Test thất bại trước vì đúng lý do, rồi mới sửa; `pnpm.cmd check` + test biên giới thật (PostgreSQL disposable, SMTP sink, storage riêng tư, browser) và báo lệnh đã chạy kèm kết quả; không dùng kết quả phiên trước.
- Không reset/migrate database không phải DB disposable tạo cho lần chạy; không sửa `.env`; không gửi email thật; không commit/push/deploy; không khôi phục snapshot S0 cũ; không thêm cơ chế đăng nhập thứ hai hay đường bỏ qua xác thực.
- Phát hiện thiết kế sai hoặc mâu thuẫn: ghi ví dụ tái hiện, dừng đúng phần đó, báo coordinator; không tự chọn bản tiện nhất, không tự đổi nghiệp vụ.
- Mỗi gói bàn giao: file đã đổi, lệnh + kết quả, bước bị bỏ qua và lý do, vấn đề còn mở, bước tiếp theo — gói khi đó _đã nộp chờ review_, dev **không** ghi `IMPLEMENTED`. **Không có gói nào "đúng" chỉ vì AI viết xong:** REVIEWER cho phán quyết `READY TO MERGE` / `CHANGES REQUESTED` / `BLOCKED` theo điều kiện ở kế hoạch mục 3; chỉ COORDINATOR (được Owner ủy quyền) tích hợp và ghi trạng thái.
