## Chuỗi lệnh deploy-từ-đầu (VPS, sau khi drop DB)

Nguồn: [seed.md](../../guides/seed.md) (mục "VPS demo đã có release mới", "Bước 1"), `scripts/ops/seed.sh`, `docker-compose.prod.yml`.
Điều kiện: release chứa `feat/z2-seed` đã deploy qua CI/CD (`deploy.yml` → `deploy-release.sh`: backup, preflight, migrate, reconcile,
recreate); container `postgres`, `minio` (bucket của `OBJECT_STORAGE_BUCKET`), `api`, `worker` chạy; `.env` (Compose: `POSTGRES_*`,
`DATABASE_DEPLOY_*`, `DATABASE_RUNTIME_*`, `MINIO_*`) và `.env.app` (ứng dụng) như cũ. **Seed ≤ 1 ngày trước demo**; lượt seed lại (không
reset) vào ngày demo cho DEMO-14 (D-Z2-1).

```bash
# Máy Owner, checkout đúng commit đang deploy:
scp scripts/ops/seed.sh .env.seed.example <demo-host>:/opt/slm/backend/
# VPS:
cd /opt/slm/backend
cp .env.seed.example .env.seed && chmod 600 .env.seed
#   điền SEED_OPERATOR_REFERENCE, SEED_SUPER_ADMIN_PASSWORD, SEED_DEMO_ACCOUNT_PASSWORD (12–128 ký tự, khác nhau),
#   SEED_SUPER_ADMIN_EMAIL (tùy chọn), SEED_ALLOW_RESET=true
# (a) DB còn (dữ liệu cũ): một lệnh làm dump → DROP/CREATE → db-admin provision → migrate → reconcile → up → apply
bash /opt/slm/backend/seed.sh --app-dir /opt/slm/backend --config /opt/slm/backend/.env.seed --confirm-reset "$(grep '^POSTGRES_DB=' .env | cut -d= -f2)"
# (b) Owner đã tự DROP DB: tạo lại rỗng, provision, rồi seed.sh tự migrate + reconcile + recreate + apply (STATE NOT_MIGRATED):
export API_IMAGE="$(head -n 1 releases/current-image)"
compose() { docker compose --project-directory "$PWD" -f "$PWD/docker-compose.prod.yml" "$@"; }
compose stop api worker
compose exec -T postgres sh -c 'psql -v ON_ERROR_STOP=1 -U "$POSTGRES_USER" -d postgres -c "CREATE DATABASE \"$POSTGRES_DB\""'
compose run --rm -T db-admin
bash /opt/slm/backend/seed.sh --app-dir /opt/slm/backend --config /opt/slm/backend/.env.seed --continue
# Ngày demo (sau hạn nộp kỳ Y = ngày seed): chạy lại, không reset — ghi điều chỉnh DEMO-14:
bash /opt/slm/backend/seed.sh --app-dir /opt/slm/backend --config /opt/slm/backend/.env.seed --continue
```

Mã thoát: 0 xong, 2 không còn gì ghi, 3 từ chối trước khi ghi, 4 có bước xung đột, 1 lỗi. Báo cáo ở `seed-reports/<UTC>-apply.txt`.

**Diễn tập local (16/11, tương đương gần nhất chạy được trên Windows):** DB trống `slm_z2_local` ⟹ `pnpm seed:local` (wrapper chạy
`prisma migrate deploy`, khởi động `dist/main` + `dist/worker`, `seed apply --allow-bootstrap`) ⟹ exit 0 (`ĐÃ CÓ 1 · ĐÃ GHI 61`); chạy
lại `pnpm seed:local --continue` ⟹ exit 2 (`ĐÃ CÓ 62`). Không diễn tập được `seed.sh`/Compose prod (cần layout `/opt/slm`, image release,
`flock`, MinIO; image MinIO không kéo được — dùng SeaweedFS S3 cho object storage). `_serial/seed-check-runtime` chạy `seed apply` bằng
runtime role với `NODE_ENV=production` (đường VPS).
